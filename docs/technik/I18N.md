# Sprachen und Übersetzungen

JoJa-CAD ist auf Deutsch geschrieben; die sichtbaren Texte stehen aber **nicht im
Code**, sondern in Sprachdateien unter `crates/jjcad-core/lang/`. Wer eine Sprache
hinzufügt, ändert Texte — und an genau **sieben Stellen** die Sprachliste in
`crates/jjcad-core/src/i18n.rs` (Abschnitt [Eine Sprache anlegen](#eine-sprache-anlegen--schritt-für-schritt)).
Fehlt ein Text in einer Übersetzung, erscheint der deutsche; das Programm stürzt
nie wegen einer Lücke ab.

`scripts/i18n-check.py` prüft den Katalog gegen den Code (Exitcode 0 = in
Ordnung, 1 = Fehler) und läuft in `cargo test` mit. Damit verrottet der Katalog
nicht unbemerkt.

---

## Quick start (English)

1. `cp crates/jjcad-core/lang/xx.toml crates/jjcad-core/lang/fr.toml`
   (`xx.toml` is an empty template: every entry is commented out, the German text
   is on the right of `=`).
2. Translate: delete the leading `# ` of a line and replace the German text.
   **Never change a key** (the part left of `=`). Keep placeholders like
   `{name}` — you may reorder them, never rename them. Untranslated lines may stay
   commented out; the German text is used instead.
3. `python3 scripts/i18n-check.py` — must end with exit code 0.
4. Register the file in `crates/jjcad-core/src/i18n.rs`: seven edits, listed in
   [step 5](#5-in-i18nrs-eintragen) below (catalogue list, `Lang` enum, `ALL`,
   `code()`, `name()`, `index()`, the `KATALOGE` array). The check script tells
   you exactly what is missing until it is done.
5. `cargo test` and `cargo build -p jjcad-gui`.
6. In the application: Einstellungen ▸ Bedienung ▸ „Sprache".

Do **not** translate: keys, `.jjcad` file-format names, MCP action IDs, numbers
and units. Details in [Was bewusst nicht übersetzt wird](#was-bewusst-nicht-übersetzt-wird).

---

## Wo die Texte liegen

| Datei | Rolle |
|---|---|
| `crates/jjcad-core/lang/de.toml` | **Quellsprache und Rückfall** — jede Änderung an einem sichtbaren Text beginnt hier |
| `crates/jjcad-core/lang/en.toml` | Englisch (vollständig seit T0106; fehlende Zeilen fielen auf Deutsch zurück) |
| `crates/jjcad-core/lang/xx.toml` | leere Vorlage für eine neue Sprache (alle Zeilen auskommentiert, wird **nicht** geladen) |

Die Dateien werden per `include_str!` einkompiliert — sie sind Teil des
Programms, es wird zur Laufzeit nichts nachgeladen. Eine Änderung braucht also
einen neuen Bau.

### Aufbau einer Sprachdatei

```toml
# Kommentar
[action.file.new]
label = "Neu"
hint  = "Neue Zeichnung anlegen"
```

Der vollständige Schlüssel ist **Tabelle + Feldname**, hier
`action.file.new.label`. Der Leser ist `i18n::lies` in
`crates/jjcad-core/src/i18n.rs`; er kennt genau drei Zeilenarten:

* `[tabelle]` — beginnt einen Abschnitt,
* `schlüssel = "text"` — ein Eintrag, Text **muss** in Anführungszeichen stehen,
* `# …` und Leerzeilen — Kommentar.

**Die Datei ist kein striktes TOML.** Sie sieht so aus, ist es aber nicht: in
`de.toml` steht `label = "Treppe"` in `[action.draw.stair]` und daneben die
Tabelle `[action.draw.stair.label]` — ein TOML-Werkzeug lehnt das ab („Cannot
overwrite a value"). Deshalb: **nicht** mit einem TOML-Editor, einem
Formatierer oder `tomllib` prüfen oder umschreiben; das Prüfskript liest mit
denselben Regeln wie das Programm. Was der Leser nicht versteht, **überspringt
er still** — genau davor schützt `scripts/i18n-check.py`.

Regeln für Einträge:

* **Ein Eintrag ist eine Zeile.** Fortsetzungen über mehrere Zeilen gibt es
  nicht; ein mehrzeiliger Text im Code wird zu einer Zeile mit `\n`.
* Escapes: `\n`, `\t`, `\"`, `\\` — sonst bleibt der Backslash stehen.
* Ein Schlüssel darf in einer Datei nur **einmal** vorkommen (der Leser
  überschreibt sonst still).
* Kein leerer Text (`label = ""`) — dann steht in der Oberfläche nichts.

### Die Abschnitte

| Abschnitt | Wofür | Beispiel |
|---|---|---|
| `action.*` | Beschriftung (`.label`) und Kurzhinweis (`.hint`) jeder Aktion — Ribbon, Inventar, Hotbar, MCP | `action.draw.wall.label` |
| `group.*` | Gruppenüberschrift der Aktionen (`ActionGroup::key`) | `group.zeichnen` |
| `ribbon.*` | Reiter und Gruppen des Ribbons | `ribbon.tab.zeichnen` |
| `ui.*` | Werte in Auswahllisten (Einfügemodus, Bogenmodus, Füllart …) | `ui.fillkind.schraffur` |
| `settings.*` | Einstellungsfenster: Titel, Suche, Kategorien | `settings.category_fangen` |
| `gui.*` | Meldungen und Beschriftungen der Oberfläche, je Quelldatei ein Abschnitt (`gui.app`, `gui.canvas`, `gui.panels`, `gui.props`, `gui.dialogs` …) | `gui.app.wand_gesetzt` |
| `test.*` | nur Vorrichtungen der Tests — **nicht übersetzen** | `test.nur_deutsch` |

Schlüssel sind **neutral und stabil** (`menu.file`, nicht „Datei"): ein Tippfehler
im deutschen Text würde sonst stillschweigend die Übersetzung verwerfen, und wer
kein Deutsch spricht, versteht den Schlüssel nicht.

## Wie ein Text ins Programm kommt

```rust
// einfacher Text
jjcad_core::i18n::tr("gui.app.wand_gesetzt")

// Text mit Werten — Platzhalter sind benannt, die Reihenfolge darf sich ändern
jjcad_core::i18n::t_args("hint.wall", &[("laenge", "5,00")])
jjcad_core::i18n::t_args_owned("gui.app.datei_geoeffnet_x", &[("pfad", pfad)])

// Kurzform
jjcad_core::t!("menu.file")
```

Nachschlagen in dieser Reihenfolge: **gewählte Sprache → Deutsch → Schlüssel
selbst**. Fehlt der Text in der gewählten Sprache, erscheint der deutsche; fehlt
er auch dort, steht der Schlüssel im Bild und im Debug-Bau warnt das Programm
einmal je Schlüssel auf stderr (`jjcad: Sprachschlüssel „…“ fehlt in
lang/en.toml`). **Kein Panic.**

Aktionen tragen ihre beiden Schlüssel in der Tabelle `actions::ACTIONS`:

```rust
act!("draw.wall", "action.draw.wall.label", Architektur, "wall", "g",
     "action.draw.wall.hint", true),
```

`ActionDef::label()`/`hint()` schlagen sie nach — ein neuer Text an einer
Aktion ist also eine Zeile in `actions.rs` plus zwei Einträge im Katalog.

**Jeder sichtbare Text der Oberfläche läuft über `tr`.** Das erzwingt
`crates/jjcad-core/tests/gui_texte.rs`: er liest die GUI-Quellen und schlägt an,
sobald wieder ein deutscher Text direkt an ein Anzeige-Bauteil geschrieben wird
(`ui.label("…")`, `RichText::new("…")`, `.on_hover_text("…")` …). Wer dort einen
Text ändert, ändert ihn **im Katalog**.

## Eine Sprache anlegen — Schritt für Schritt

Beispiel: Französisch, Sprachcode `fr` (ISO 639-1, zwei Kleinbuchstaben).

### 1. Sprachcode wählen

Zwei bis drei Kleinbuchstaben, der Code ist gleichzeitig der Dateiname
(`fr.toml`) und der Wert in `prefs.json` (`"language": "fr"`). Er darf nicht
`xx` sein — das ist die Vorlage.

### 2. Vorlage kopieren

```bash
cp crates/jjcad-core/lang/xx.toml crates/jjcad-core/lang/fr.toml
```

Die Vorlage enthält **jeden** Schlüssel des deutschen Katalogs als Kommentar,
mit dem deutschen Text hinter `=`. Sie wird aus `de.toml` erzeugt:

```bash
python3 scripts/i18n-check.py --vorlage crates/jjcad-core/lang/xx.toml
```

(Nach jedem neuen Schlüssel in `de.toml` neu erzeugen; das Prüfskript warnt,
wenn die Vorlage hinterherhinkt.)

### 3. Übersetzen

In `fr.toml` das führende `# ` einer Zeile löschen und den deutschen Text
rechts vom `=` ersetzen:

```toml
[action.file.new]
# hint = "Neue Zeichnung anlegen"     ← bleibt auskommentiert: Rückfall Deutsch
label = "Nouveau"                     ← übersetzt
```

* **Schlüssel nie ändern**, nur den Text.
* **Platzhalter erhalten**: `{name}`, `{wert1}`, `{anzahl}` … dürfen verschoben,
  aber nicht umbenannt oder weggelassen werden — sonst bleibt die Klammer im
  Text stehen bzw. der Wert fehlt.
* Nicht übersetzte Zeilen dürfen auskommentiert bleiben.
* Umlaute und Sonderzeichen sind kein Problem: die Datei ist UTF-8.

### 4. Prüfen

```bash
python3 scripts/i18n-check.py
```

Solange die Sprache nicht eingetragen ist, meldet das Skript
„nicht in KATALOG_QUELLEN eingetragen“ (Exitcode 1) — weiter mit Schritt 5.
Danach muss der Lauf mit `0 Fehler` enden.

### 5. In `i18n.rs` eintragen

Sieben kleine Änderungen in `crates/jjcad-core/src/i18n.rs`. Jede Stelle ist
unten mit dem aktuellen Stand (Deutsch + Englisch) gezeigt; für Französisch
kommt die dritte Zeile dazu.

**(a) Katalogliste** — die Zahl in eckigen Klammern ist die Anzahl:

```rust
const KATALOG_QUELLEN: [(&str, &str, &str); 3] = [
    ("de", "Deutsch", include_str!("../lang/de.toml")),
    ("en", "English", include_str!("../lang/en.toml")),
    ("fr", "Français", include_str!("../lang/fr.toml")),   // neu
];
```

**(b) Die Aufzählung `Lang`** — je Sprache eine Variante mit `serde`-Namen:

```rust
pub enum Lang {
    #[default]
    #[serde(rename = "de")]
    Deutsch,
    #[serde(rename = "en")]
    Englisch,
    #[serde(rename = "fr")]
    Franzoesisch,          // neu — Rust-Bezeichner ohne Akzente
}
```

**(c) Die Liste der wählbaren Sprachen:**

```rust
pub const ALL: [Lang; 3] = [Lang::Deutsch, Lang::Englisch, Lang::Franzoesisch];
```

**(d) Sprachcode** in `code()`:

```rust
Lang::Franzoesisch => "fr",
```

**(e) Eigenbezeichnung** in `name()` — sie wird **nicht** übersetzt, sie steht so
in jeder Oberfläche:

```rust
Lang::Franzoesisch => "Français",
```

**(f) Platz in der Katalogliste** in `index()` — 0, 1, 2 … in derselben
Reihenfolge wie (a):

```rust
Lang::Franzoesisch => 2,
```

**(g) Der Zwischenspeicher** — ebenfalls die Anzahl, und ein Eintrag im Feld:

```rust
static KATALOGE: OnceLock<[Katalog; 3]> = OnceLock::new();

fn kataloge() -> &'static [Katalog; 3] {
    KATALOGE.get_or_init(|| {
        [
            lies(KATALOG_QUELLEN[0].2),
            lies(KATALOG_QUELLEN[1].2),
            lies(KATALOG_QUELLEN[2].2),
        ]
    })
}
```

Vergisst man (g), startet das Programm nicht (die Feldlänge passt nicht zu (a));
vergisst man (c), wird die Sprache nie angeboten; vergisst man (d), meldet das
Prüfskript den fehlenden Code. **Alle drei prüft das Skript**, bevor gebaut wird.

### 6. Bauen und prüfen

```bash
cargo test            # muss grün sein
cargo build -p jjcad-gui
```

`crates/jjcad-core/tests/i18n_katalog.rs` prüft unter anderem, dass jede Aktion
in beiden Katalogen eine Beschriftung hat; `tests/i18n_pruefskript.rs` ruft das
Prüfskript auf.

### 7. Im Programm ausprobieren

Einstellungen ▸ Bedienung ▸ „Sprache“ — die Sprache steht in einem
**Auswahlfeld**: geschlossen zeigt es die eingestellte Sprache, aufgeklappt die
ganze Liste (`i18n::Lang::ALL`), damit auch eine längere Liste unterstützter
Sprachen Platz hat. Der Wechsel wirkt **sofort**, ohne
Neustart, und wird in `~/.config/jjcad/prefs.json` gespeichert (`"language":
"fr"`). Die Einstellung gilt für die Oberfläche; gezeichnete Texte bleiben, was
sie sind (Zeichnungsinhalt wird nicht übersetzt).

## Das Prüfskript

```bash
python3 scripts/i18n-check.py              # Tor: 0 = sauber, 1 = Fehler
python3 scripts/i18n-check.py --streng     # unvollständige Übersetzung = Fehler
python3 scripts/i18n-check.py --vorlage    # Vorlage auf stdout
python3 scripts/i18n-check.py --selbsttest # prüft das Prüfskript selbst
```

| Prüfung | Ergebnis |
|---|---|
| Schlüssel im Code benutzt, in `de.toml` nicht vorhanden | **Fehler** |
| Schlüssel in `de.toml`, im Code nirgends benutzt (verwaist) | **Fehler** |
| Platzhalter fehlt / ist überzählig / hat keinen Namen (`{}`) | **Fehler** |
| Schlüssel doppelt in einer Datei | **Fehler** |
| leerer Wert | **Fehler** |
| Wert ohne Anführungszeichen, unlesbare Zeile, kaputte Klammer | **Fehler** |
| Sprachdatei nicht in `KATALOG_QUELLEN` / Code fehlt in `Lang::code()` | **Fehler** |
| Schlüssel, den nur eine Übersetzung kennt (in `de.toml` gelöscht) | **Fehler** |
| Schlüssel einer Übersetzung fehlt (Rückfall Deutsch) | Warnung (`--streng`: Fehler) |
| Text deutlich länger als deutsch (Ribbon, Gruppen, Auswahlwerte) | Warnung |
| `lang/xx.toml` hinter dem Katalog zurück | Warnung |
| Schlüssel außerhalb der Katalogabschnitte | Warnung |

Typische Meldung und was zu tun ist:

```
de.toml:1139: Schlüssel „gui.panels.keine_objekte“ wird nirgends benutzt (verwaist)
```

Der Text ist tot: entweder wurde die Stelle im Code entfernt (dann Zeile
löschen), oder der Schlüssel heißt anders (dann Aufruf und Katalog angleichen).

```
en.toml:424: Platzhalter passen nicht zu de.toml („gui.app.datei_bereits_offen_x“): fehlt {wert1}
```

Die Übersetzung hat den Platzhalter verloren oder umbenannt — die Klammer bliebe
im Text stehen.

```
de.toml:822: Platzhalter „{}“ bei „gui.canvas.x_enter_laenge“ hat keinen Namen
```

`{}` wird von `i18n::fuellen` **nicht** ersetzt (es sucht `{name}`), die Klammer
steht dann im Bild. Der Platzhalter braucht den Namen, den die Aufrufstelle
übergibt (`{eingabe}`).

`--selbsttest` baut drei Fehler in eine Wegwerfkopie ein (fehlender Schlüssel,
leerer Wert, falscher Platzhalter), prüft, dass alle drei gefunden werden, und
dass der saubere Bestand 0 ergibt. Damit ist das Skript selbst abgesichert.

## Was bewusst nicht übersetzt wird

* **Das Dateiformat `.jjcad`** — Feldnamen (`entities`, `thickness`), Aufzählungen
  (`"wall"`, `"left"`, `"sans"`), Ebenen- und Blattnamen. Eine Datei muss in
  jeder Sprache gleich gelesen werden; übersetzte Feldnamen wären ein neues
  Format. Siehe `docs/technik/FORMAT.md`.
* **MCP-Action-IDs und Parameter** (`draw.wall`, `modify.set`, `units`, `pts`,
  Werkzeugnamen `jjcad_execute`, `jjcad_batch`). Das ist die Schnittstelle für
  Programme und KI-Agenten, kein Anzeigetext; sie steht in `docs/technik/MCP.md`.
* **Tastenkürzel-Schreibweisen** (`ctrl+s`, `shift+v`) und die Tasten selbst.
* **Zahlen, Einheiten, Datum** — `3,50 m`, `12,4 m²`, `mm`/`cm`/`m`, Winkel in
  Grad mit Komma. Die Ausgabe rechnet und formatiert in `units.rs`; die Sprache
  ändert daran nichts. Wer für Englisch `3.50` will, ändert `units.rs`, **nicht**
  den Katalog (und muss dann PDF/PNG-Tests mitziehen).
* **Eigennamen und Normbezeichnungen** — JoJa-CAD, DIN 1356, DIN 1451,
  EN ISO 3098, Liberation, DXF, PDF.
* **Zeichnungsinhalt** — Texte, die der Nutzer in die Zeichnung schreibt, und
  das Schriftfeld sind Daten, keine Oberfläche.
* **`test.*`** — Vorrichtungen der Tests (`test.nur_deutsch` prüft den Rückfall).
* **Die Eigenbezeichnung einer Sprache** in `Lang::name()` — sie steht in jeder
  Oberfläche in ihrer eigenen Sprache („Deutsch“, „English“, „Français“).

## Textlänge im Ribbon

Die Schaltflächen im Ribbon sind **70 px** breit (geteilte Schaltflächen 74 px),
Gruppen und Reiter teilen sich dieselbe Breite. Passt eine Beschriftung nicht,
verkleinert `widgets::passende_schriftgroesse` die Schrift bis auf **8 Punkt**;
darunter wird nicht weiter verkleinert — dann ist der Name zu lang.

* Beschriftungen (`.label`, `ribbon.*`, `group.*`, `ui.*`): **1–2 Wörter, höchstens
  etwa 12 Zeichen**. Lieber kürzen als abschneiden.
* Kurzhinweise (`.hint`) stehen als Tooltip und in der Statuszeile — dort darf
  der Text lang sein.
* Der Reiter „Ansicht“ liegt mit 1076 px schon an der Mindestfensterbreite
  1080 px (`reiter_ansicht_passt_in_die_mindestbreite`); eine Übersetzung ändert
  die Breite nicht, sehr lange Wörter sprengen aber die Schaltfläche optisch.
* Das Prüfskript warnt, wenn eine Beschriftung mehr als das 1,4-Fache der
  deutschen Länge (plus 8 Zeichen) erreicht.

## Schriftabdeckung

Ein Text wird in der Schrift gezeichnet, die **am Textobjekt** steht — nicht in
einer, die zur Sprache passt. Kennt die Schrift ein Zeichen nicht, wird es
**nicht gezeichnet**: es entsteht eine Lücke (die Breite stimmt trotzdem, damit
der Satz nicht verrutscht), im PDF fehlt es ganz.

Gemessen an den mitgelieferten technischen Schriften
(`crates/jjcad-core/fonts/`, Zeichen im `cmap`):

| Schrift | Zeichen | Abdeckung |
|---|---|---|
| D-DIN / D-DIN Condensed (DIN 1451 Mittel-/Engschrift) | 231 | Deutsch und Westeuropa: `ä ö ü ß é ñ € — ·` ja; `ł ř ğ İ` nein; kein Griechisch, kein Kyrillisch, kein CJK |
| D-DIN Expanded (DIN 1451 Breitschrift, gestreckt) | wie D-DIN | dieselbe Abdeckung |
| osifont (EN ISO 3098 Typ A) | 995 | zusätzlich Griechisch und Kyrillisch; kein CJK |
| Systemschriften (Liberation Sans/Serif/Mono/Narrow, Quicksand) | je Rechner | mehr oder weniger; am Zielrechner prüfen |

Für Sprachen außerhalb Latein-1 gilt deshalb: die **Systemschrift** (Serifenlos)
verwenden, nicht die technischen Schriften — und am Zielrechner nachsehen.
Für Chinesisch, Japanisch, Koreanisch, Arabisch oder Hebräisch fehlt die
Schriftgrundlage; das wäre ein eigenes Ticket (Schriftdatei mitliefern).

Prüfweg: ein Textfeld mit den Sonderzeichen setzen und zoomen, oder ohne GUI
ein Bild schreiben:

```bash
cargo run --example zeichnung_png -- samples/Wohnhaus.jjcad /tmp/probe.png
```

## Prüfen im Alltag

```bash
python3 scripts/i18n-check.py                 # Katalog gegen Code
cargo test -p jjcad-core --test i18n_katalog  # Katalog + Vorlage
cargo test -p jjcad-core --test gui_texte     # kein deutscher Text direkt in der GUI
cargo test -p jjcad-core --test i18n_pruefskript  # ruft das Prüfskript auf
```

Nach jeder Änderung an einem sichtbaren Text: Schlüssel in `de.toml` ändern,
`python3 scripts/i18n-check.py`, `cargo test`. Ein neuer Schlüssel gehört
zusätzlich in die Vorlage (`--vorlage`).

## Grenzen

* **Die Sprachliste ist eine Aufzählung.** Eine Sprache braucht die sieben
  Änderungen aus Schritt 5 — ohne Rust-Kenntnisse geht es nicht. Das Skript
  findet jede vergessene Stelle, aber es kann sie nicht für dich eintragen.
* **Keine Pluralformen, kein Genus.** `{anzahl} Blätter` bleibt „1 Blätter“;
  wer das braucht, muss im Code zwei Schlüssel abfragen.
* **Keine sprachabhängigen Zahlenformate** (siehe oben).
* **Einige Auswahlwerte kommen aus dem Kern und brauchen dort einen Schlüssel:**
  Türart (`model::DoorKind`), Maßachse (`model::DimAxis`), Schriftart
  (`model::TextFont`), Ausrichtung, Muster (`style::FillPattern`), Linientyp,
  Pfeilart, Wandausrichtung, Einheit, Ziehen, Drehpunkt und Fensterrahmen
  (`persist`), Fangart (`snap::SnapKind`). Sie tragen **zwei** Namen:
  `label()` bleibt der deutsche Name (Dateien, Action-Parameter, Tests) und
  `text()` schlägt den Katalog nach (`ui.<aufzählung>.<variante>`, z. B.
  `ui.doorkind.hinge`). Die Oberfläche ruft **`text()`**, nie `label()` —
  `crates/jjcad-core/tests/i18n_katalog.rs` prüft beides. Ein neuer Wert einer
  Aufzählung bekommt beide Namen und den Schlüssel in `de.toml` **und**
  `en.toml`.
* **Ein Sprachwechsel gilt für neue Bilder.** Bereits gezeichnete Texte sind
  Zeichnungsinhalt und ändern sich nicht.
* **Der Rückfall ist deutsch.** Eine Übersetzung, die einen Schlüssel nicht
  kennt, zeigt Deutsch — nie Englisch. Das ist Absicht: Englisch ist keine
  Zwischensprache.
